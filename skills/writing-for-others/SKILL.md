# Writing for other people, in the user's name

The reader must not be able to tell an AI drafted it. That comes from **content** (real facts, one clear point, the user's tone), not from tricks: no rare synonyms, no hidden characters. The one exception is the occasional typo in informal channels (§2).

## 1. Facts first

- Only facts the user gave or that are on record (their CV, the thread, their files). **Never invent** a memory, an emotion, an anecdote, a number, a shared acquaintance or a "lifelong passion".
- Unsure whether something is true or whether the user would say it → ask, or leave it out.
- Job applications: also follow `~/dev/job-applications/docs/human-writing-guide.md` (truth rules, detectors, review steps).

## 2. Sound like the user

- **Language and register of the thread**: answer in the language the other person used; match their length and formality. A WhatsApp reply is one or two lines, not a letter.
- Lead with the point: the answer, the request, or the reason for writing. Then only what the reader doesn't already know.
- Short plain words, active verbs, concrete details ("Tuesday 14:00 works", not "I remain at your disposal regarding scheduling").
- If the user's own past messages to this person exist (Gmail sent, WhatsApp, LinkedIn), read two or three first and copy their greeting, sign-off, tone and length, but never their UTF-8 emojis (§3).

| Context | Default tone (until the user says otherwise) |
|---|---|
| recruiter, employer, administration | formal, short, direct; formal greeting and closing |
| colleague, professional contact | friendly-professional, first name, no ceremony |
| friends, family | the user's own style from past messages; never formal |

**Typos in informal channels** (the user's rule): WhatsApp, Signal, SMS and chat messages, written in a casual tone, get the occasional typo, the way a person typing fast on a phone writes.

| | Rule |
|---|---|
| Where | informal channels and a casual tone only. Never in an email to a recruiter, employer or administration, a cover letter, a CV, a LinkedIn profile, a form or a post |
| How many | sparse: at most one per message, and not in every message |
| Kind | one missing letter in a common word ("realy", "tomorow", "thnks"), nothing more elaborate |
| Never in | names, numbers, dates, times, addresses, links, or the word the message hinges on |
| When proposing | point it out in one line ("deliberate typo: realy"), so the user can keep or fix it |

## 3. Remove the AI tells

Fix each one by rewriting the sentence around its point, not by swapping a word.

| Tell | Instead |
|---|---|
| "not just X but Y", "this isn't about X, it's about Y", arguing with no one | state the point directly |
| triplets and balanced parallel sentences, every paragraph the same length | as many items as there really are; shape by content |
| one-line dramatic closers, aphorisms, "the real question is…" | cut; end when the content ends |
| stock words: delve, pivotal, showcase, leverage, foster, seamless, robust, holistic, cutting-edge, transformative, intricate, underscore | the plain word, or the actual action |
| praise and inflation: "perfect fit", "thrilled to", "unique blend", "game-changer", legacy and bright futures | the specific fact or motivation |
| "Furthermore / Moreover / Additionally" at every paragraph | drop unneeded connectors |
| em dashes everywhere, bold, headings, bullet lists in a message | commas and periods; plain prose in messages |
| chatbot residue: "I hope this finds you well", "Great question", "Feel free to reach out", "Let me know if you have any questions", "N'hésitez pas à…" | a real closing, or none |
| stacked hedges, "serves as / boasts" instead of "is / has", trailing "-ing" clauses | simple verbs, one hedge only if needed |
| UTF-8 emojis (🙂 😊 👋 🚀 ✅), even when the user's past messages contain some: they read as LLM-written | ASCII smileys such as `:)` or `:D`, or none |

## 4. Before it goes out

1. Read it aloud as the user: would they say each sentence, and could they explain it if asked? If not, change it.
2. Search the draft for the tells that survive most: contrasts, closers, triplets, dashes, stock words, UTF-8 emojis.
3. Give the user the final text. Sending it is the channel's job (its own skill), with the user's OK.
